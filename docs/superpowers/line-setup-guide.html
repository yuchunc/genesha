Getting the LINE channel secret & access token

There's no self-serve API key endpoint for LINE — credentials are issued through the LINE Developers Console by hand. This is the exact path from zero to a verified, working webhook for the AI chat assistant.

1 · Console 2 · Provider 3 · Channel 4 · Secret 5 · Token 6 · Webhook 7 · Auto-replies 8 · Bot ID / QR 9 · Teacher ID 10 · Boot & verify
1

Open the LINE Developers Console

Go to developers.line.biz/console/ and log in with a LINE account (the teacher's own account is fine, or a shared studio account).

This is separate from a normal LINE user login — it's the same account, just a developer-facing console layered on top.

2

Create a Provider

A Provider is the top-level org that owns channels — e.g. "Ganesha Studio". Create one if this is the first channel; reuse an existing provider otherwise.

3

Create a Messaging API channel

Inside the provider: Create a new channel → Messaging API. Fill in channel name, description, category/subcategory, and upload an icon (required to finish creation).

This channel is the bot identity — the account the teacher and students add as a LINE friend.

4

Copy the channel secret

On the channel's Basic settings tab, scroll to Channel secret.

This is LINE_CHANNEL_SECRET — VerifySignaturePlug HMAC-SHA256's the raw webhook body against it to authenticate every inbound request.

5

Issue a channel access token

On the Messaging API tab, scroll to Channel access token and click Issue for a long-lived token (newer channels may only offer the stateless/JWT-based v2.1 token — the console tells you which is available).

This is LINE_CHANNEL_ACCESS_TOKEN — the bearer token Ganesha.Line.Client sends on reply, push, and get_group_member calls.

Treat it like a secret. Regenerating invalidates the old token immediately — rotate on leak, not on a schedule.
6

Point the webhook at your server

Expose the app publicly first, e.g.:

cloudflared tunnel --url http://localhost:4000

Then on the Messaging API tab, set Webhook URL to:

https://<your-tunnel-or-domain>/line/webhook

Click Verify — LINE POSTs a test event and expects 200. A 403 means the secret configured on the server doesn't match the console. Toggle Use webhook to on.

7

Turn off LINE's own auto-responses

Same Messaging API tab:

  • Auto-reply messages — Disabled
  • Greeting messages — Disabled

Leaving these on makes LINE's canned replies race with the assistant's real reply.

8

Grab the bot's basic ID / QR code

Also on Basic settings. This is how the teacher and students add the bot as a friend, and how it gets invited into the student group chat.

9

Find the teacher's LINE user ID

TEACHER_LINE_USER_ID is not in the console — it's a personal LINE userId, discovered at runtime.

  1. Boot the server with the secret/token above and any placeholder teacher ID.
  2. Have the teacher add the bot as a friend and send it any message.
  3. Read source_id off the newest row: 
    select source_id from line_events order by id desc limit 1;
  4. Restart the server with that value.
Fail-closed by design: until this is set correctly, teacher messages fall through route/2's default clause and nothing happens — that's intentional, not a bug.
10

Boot with real credentials

LINE_CHANNEL_SECRET=<from step 4> \
LINE_CHANNEL_ACCESS_TOKEN=<from step 5> \
TEACHER_LINE_USER_ID=<from step 9> \
ANTHROPIC_API_KEY=sk-ant-<your key> \
mix phx.server

  • 1:1 to the bot: "小美轉了 3200 給我" → reply with 確認/捨棄 quick replies → tap 確認 → confirmed in-app
  • Same message posted in the student group → zero bot replies in the group, row recorded in assistant_messages
